2. 2026年度 ギミック予想と実装方針（逆引き辞典）
パターンA：多段バウンド（複数枚の板や壁での反射）
特徴: 空中で2回以上バウンドする。

方針: 平面の方程式 ax+by+cz+d=0 と放物線の方程式を連立させ、二次方程式の解の公式で「交点となる時間 t」を計算する。

実装メモ:
ld a = 0.5 * normal.dot(A);
ld b = normal.dot(v_init);
ld c = normal.dot(p_init - p0);

パターンB：動的ターゲット（コンベア・振り子など）
特徴: ターゲットが時間とともに移動する。

方針: 着弾点の距離評価を target_pos ではなく get_target_pos(t) に変更する。

実装メモ: シミュレータが返す「着弾時間 t」をターゲットの移動関数に渡し、「着弾した瞬間のターゲットの未来位置」と「実際の着弾点」の距離を評価して最適化する（偏差射撃）。

パターンC：空中回転障害物（3D線分交差）
特徴: 空中で回転する棒や障害物を避ける。

方針: 連続衝突判定（CCD）の導入。

実装メモ: dt の間に玉が動いた「軌跡（線分）」と、障害物（線分）の「3次元空間における2線分間の最短距離」を測る関数を必ず用意する。点同士の判定では高速な玉が障害物をすり抜ける（トンネリング現象）。

パターンD：空気抵抗・マグヌス効果（非線形物理）
特徴: 重力以外の力が速度に応じて変化する（二次方程式が通じない）。

方針: 4次ルンゲ＝クッタ法（RK4）の採用。

実装メモ: 状態（位置、速度）の微分関数（速度、加速度）を定義し、dt の間に4回傾きをサンプリングして加重平均を取る。着弾の瞬間はZ座標が0を跨いだフレーム間で「二分探索」を行い、厳密な着弾時間を特定する。

パターンE：単純な制約追加（壁越え・板のサイズ制限・グリッド移動）
特徴: 物理法則は変わらないが、ペナルティや無効条件が増える。

方針: O(1) 解析解の中に if 文の条件を足すだけ。

実装メモ:

壁越え: if (y_hit_wall && z_at_wall < WALL_HEIGHT) return false;

板制限: if (hypot(hit_x, hit_y) > PLATE_RADIUS) return false;

3-2. エネルギー枯渇バグ（実行順序の罠）
現象: 遠くのターゲットに対してAIが諦め、初期値（5000, 0）を出力する。

原因: 余ったダミー行（空撃ち）を先に消費すると、バウンド盤の高さ（Z

​

対策: 本命のターゲットを一番高さが低い序盤（i=0,1,…）にすべて撃ち切り、余ったダミーは必ず一番最後に nu=0（球数0）で出力して時間を消化する。

3-3. 時間制限（100秒ルールの壁）
現象: 最後の数球が0点になる。

対策: 内部タイマー（sim_time_ms）を厳格に管理する。
1回のアクションにかかる時間は 軸移動時間(1500ms) + 待ち時間(Wt)。
ダミー行動の Wt は最小の 2000 に設定し、全体の時間を節約する。
